---
title: "Transferir conversa"
api: "POST /channel-api/chats/{id}/transfer"
description: "Transfere a conversa para uma equipe ou para um usuário"
authMethod: "none"
---

<ParamField header="Authorization" type="string" required>
  API key de conta no formato `ApiKey <token>`. Scope exigido: `chats:transfer`. Veja [API key de conta](/guias/introducao#api-key-de-conta).
</ParamField>

<ParamField path="id" type="string" required>
  ID da conversa. Conversa inexistente ou de canal fora da key retorna `404`.
</ParamField>

<ParamField body="teamId" type="string">
  Equipe de destino. A conversa vai para a fila `Espera` da equipe, sem atendente. Informe `teamId` **ou** `userId`, nunca os dois.
</ParamField>

<ParamField body="userId" type="string">
  Usuário de destino. A conversa fica `Em Atendimento` com esse usuário, mesmo que outro já estivesse atendendo. Informe `teamId` **ou** `userId`, nunca os dois.
</ParamField>

<ParamField body="reasonCode" type="string">
  Código do motivo, registrado no evento de transferência. Até 100 caracteres.
</ParamField>

<ParamField body="reason" type="string">
  Motivo em texto livre. Até 500 caracteres.
</ParamField>

<Note>
  Para só pegar uma conversa da fila, sem tirar de ninguém, use [Capturar atendimento](/api-reference/endpoint/capturar-atendimento). Os IDs de destino vêm de [Listar equipes](/api-reference/endpoint/listar-equipes) e [Listar usuários](/api-reference/endpoint/listar-usuarios).
</Note>

## Resposta

Conversa após a transferência.

<ResponseField name="id" type="string">
  ID da conversa.
</ResponseField>

<ResponseField name="status" type="string">
  `open`.
</ResponseField>

<ResponseField name="queue" type="string">
  `Espera` (transferência para equipe) ou `Em Atendimento` (transferência para usuário).
</ResponseField>

<ResponseField name="channelId" type="string | null">
  Canal da conversa.
</ResponseField>

<ResponseField name="teamId" type="string | null">
  Equipe da conversa.
</ResponseField>

<ResponseField name="userId" type="string | null">
  Atendente após a transferência. `null` na transferência para equipe.
</ResponseField>

<ResponseField name="contact" type="object | null">
  `id` do contato. `name` e `value` vêm `null` nesta resposta.
</ResponseField>

<ResponseField name="unreadMessages" type="integer">
  Mensagens não lidas.
</ResponseField>

<ResponseField name="lastMessage" type="object | null">
  Resumo da última mensagem: `origin` e `content` (`type`, `value`).
</ResponseField>

<ResponseField name="createdAt" type="string">
  Criação, ISO 8601.
</ResponseField>

<ResponseField name="updatedAt" type="string">
  Última atualização, ISO 8601.
</ResponseField>

<RequestExample>

```bash Para equipe
curl -X POST "https://chat.zazzinternet.com/channel-api/chats/66f2a1c9e4b0a1b2c3d4e5f6/transfer" \
  -H "Authorization: ApiKey zk_live_SEU_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "teamId": "66f1f0c2e4b0a1b2c3d4e100",
    "reasonCode": "ERP_ROUTING",
    "reason": "Cliente com fatura em atraso"
  }'
```

```bash Para usuário
curl -X POST "https://chat.zazzinternet.com/channel-api/chats/66f2a1c9e4b0a1b2c3d4e5f6/transfer" \
  -H "Authorization: ApiKey zk_live_SEU_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "userId": "66f1f0c2e4b0a1b2c3d4e200" }'
```

</RequestExample>
